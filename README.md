# SystemVerilog checker library

This library provides 29 reusable SystemVerilog checker families. Each family
is implemented as a true `checker` / `endchecker` declaration generated by a
typed declaration macro, with a parameterized module host for common
configurations. The library is a draft and its qualification limits are listed
in [tool support](docs/tool_support.md).

Checkers validate sampled behavior supplied by their caller. Event inputs mean
accepted events only when the caller defines them that way; a held `valid` level
is not implicitly treated as repeated acceptance. The caller owns clocks,
resets, acceptance policy, expected values, storage visibility, timing policy,
and topology. Each checker owns only its local bounded reference state and
assertions. Reset or disable clears its model and cancels pending obligations as
defined by the individual contract.

## Checker families

- **Signals and state:** `known_check`, `stable_check`, `encoding_check`,
  `counter_check`, `pulse_check`, and `reset_check`.
- **Accepted work:** `event_conservation_check`, `handshake_check`,
  `fifo_check`, `credit_check`, `ordering_check`, `data_integrity_check`, and
  `cancellation_check`.
- **Address, registers, and policy:** `address_check`, `length_check`,
  `register_check`, `configuration_check`, `error_propagation_check`,
  `interrupt_check`, `access_control_check`, `locking_check`,
  `zeroization_check`, `quiescence_check`, `ownership_check`, and
  `fairness_check`.
- **Clocks:** `clock_timing_check`, `clock_alive_check`, `clock_gate_check`,
  and `clock_divider_check`.

See [behavioral contracts](docs/contracts.md) for port meanings, parameter
policies, event precedence, reset and disable behavior, and limitations. The
[test specification](docs/test_specification.md) describes the fixture cases.

## Declaration and parameter use

SystemVerilog checkers have typed ports but no module-style parameter override
syntax. Each `SVA_DECLARE_*` macro emits a named, typed checker declaration
whose widths, capacities, and policy values are compile-time constants. For
example:

```systemverilog
`include "known_check.svh"
`include "stable_check.svh"

`SVA_DECLARE_KNOWN_CHECK(known_byte_check, 8)
`SVA_DECLARE_STABLE_CHECK(stable_byte_check, 8)

module byte_checks (
    input logic clk,
    input logic reset_n,
    input logic enable,
    input logic hold,
    input logic [7:0] value,
    input logic [7:0] valid_mask
);
    known_byte_check u_known_check (
        clk, reset_n, enable, value, valid_mask
    );
    stable_byte_check u_stable_check (
        clk, reset_n, enable, hold, value, valid_mask
    );
endmodule
```

Parameterized module hosts such as `known_check #(.WIDTH(8))` are provided for
convenient typed instances. Their nested checker declarations elaborate with
strict slang. Verilator's runtime path uses checker declarations emitted at
compilation-unit scope because Verilator does not support the nested declaration
form; see [tool support](docs/tool_support.md).

## Build and license

Use `checkers.f` from this directory as the library source list. It compiles
each `.sv` host once; each host includes its corresponding `.svh` declaration
macro. Do not compile those include fragments separately. For direct macro use,
add `src` to the include path, include only the needed `.svh` files in a source
unit, and compile that source once.
